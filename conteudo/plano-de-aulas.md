# AI Engineering Foundations and Competition Practice

Six weeks · 12 recorded lessons · 24 hours of study · Optional online office hours

How do you decide what a model should learn, what evidence it needs and whether its output is useful? You will answer those questions with images, tables, text and time-stamped events. The conveyor is one competition case study. Each week you will also consider where the same method would work elsewhere and where its assumptions break down.

## Weekly programme

Each lesson has a captioned recording, a short reading and a practical assignment. Budget four hours per week. Across the course, allow about 40 minutes per week for video, 40 for reading, 140 for practical work and 20 for reviewing and submitting evidence. In the final week, reserve 120 minutes of practical time for the mock challenge.

| Lesson | Recorded demonstration | Reading | Exercise and submission |
|---|---|---|---|
| 1.1 · How machines learn: grouping colours with K-means | Compare a hand-written colour rule with a palette learned from a photograph. Predict and then inspect the effect of changing K. | Features, examples, labels, supervised and unsupervised learning, centroids and distance. | Run the [colour clustering lab](week-01/kmeans-colour-lab.ipynb). Submit three palettes, a lighting experiment and an explanation of one grouping that is unhelpful for recognising objects. [Lesson and marking criteria](week-01/lesson-1-1.md) |
| 1.2 · Turn a question into a dataset | Frame three tasks using the same building records: group similar days, predict electricity use and flag unusually high demand against a specified limit. | Unit of observation, target, feature availability, missing values, scaling and leakage. | Build a data dictionary. Mark which features are available at prediction time, split daily records chronologically and explain one misleading feature you excluded. |
| 2.1 · Predict a number | Predict daily electricity use from weather and building schedules. Compare a training-set mean with linear regression on later days. | Regression, train versus test error, residuals, mean absolute error and its units. | Submit baseline and model errors in kWh on the same held-out days. Plot residuals and describe one condition where the model performs poorly. |
| 2.2 · Predict a category | Classify labelled support messages by topic using word counts and logistic regression. Compare against the most frequent training label. | Classification, confusion matrices, class imbalance, macro F1 and the privacy of example messages. | Use synthetic or anonymised messages. Split by conversation before fitting the vocabulary. Submit a confusion matrix, macro F1 and two errors with plausible explanations. |
| 3.1 · Build an image dataset | Capture short conveyor clips under different lighting and viewpoints. Label boxes and track which frames show the same physical sample. | Image acquisition, normalised box coordinates, annotation consistency and leakage between adjacent frames. | Submit a class inventory, annotated examples and a split manifest. Keep repeated appearances of a sample together. Identify one underrepresented condition. |
| 3.2 · Train and compare object detectors | Train a small baseline detector and compare two configurations on the same held-out clip. | Precision, recall, mAP, confidence thresholds, inference time and model versioning. | Submit the dataset version, training command and per-class results. Explain a missed detection and justify a configuration using both quality and latency. |
| 4.1 · Infer depth and measure height | Rectify a stereo pair, measure disparity and estimate an object's height above a reference plane. | Correspondence, camera geometry, focal length in pixels, baseline, reference frames and measurement uncertainty. | Submit measurements in millimetres for three reference objects, the mean absolute error and an example that should be rejected because correspondence is unreliable. |
| 4.2 · Make predictions on a live stream | Run the same pipeline on recorded and live input. Follow one object across frames and interrupt the stream. | Timestamps, buffering, repeated detections, event identity and latency measurement. | Submit a time-stamped trace, event count against a labelled clip, measured latency and the outcome after reconnection. Explain how the same issue could affect a traffic counter. |
| 5.1 · Connect a model to an application | Feed a prediction into a decision rule. Compare routing an uncertain support request to a person with sending an accepted vision result to the robot simulator. | Model output contracts, thresholds, abstention, coordinate frames and command acknowledgements. | In the simulator, test a valid target, an invalid target and a communication failure. Submit the prediction, decision and response for each. Explain when to ask for human review. |
| 5.2 · Evaluate the complete system | Replay a known sequence from input to decision to outcome. Trace a missed or repeated action to its source. | Event reconciliation, input shift, end-to-end testing and the emergency-stop procedure for a supervised physical trial. | Submit a trace per object and one regression test for a failure you observed. Use the simulator for assessment. A supervised cell trial is optional when available. |
| 6.1 · Choose a baseline in a new domain | Examine a building-maintenance dataset and choose a target, split and metric before fitting a model. | Task framing, error costs, reproducibility and communicating limitations to a user. | Submit a rerunnable notebook, baseline score, improvement attempt and one limitation. Explain which earlier technique transferred and which assumption changed. |
| 6.2 · Individual mock challenge | Walk through a small example of packaging predictions and checking that someone else can reproduce them. | Time planning, submission format and a short retrospective. | In 120 minutes, solve a new practice task outside the conveyor setting. Submit predictions, model or fitted pipeline, run command and a short decision note. Official surprise-module data remain restricted. |

## Feedback and office hours

Your trainer will post a rubric before each assignment and give one concrete improvement to try after each submission. Weekly feedback focuses on problem framing and data quality, comparison against a baseline, evaluation on unseen samples, reliability over time, traceable decisions and independent reproduction.

Use **Book an office hour** at the top of the course to choose an available 20-minute online slot in Abu Dhabi time. Include the lesson, what you tried and the question you would like to discuss. After the meeting, record your next experiment in the assignment.

## Moodle publishing notes for the trainer

Create one section per week and two lessons per section. Set the course language to English. Publish English activity titles, narration, captions, readings, assignments, rubrics and booking instructions. Keep each video, reading and practice file together on a Moodle Page and collect evidence with an Assignment. Use practice data cleared for the class and keep marking references restricted to trainers. Before releasing each week, test the files, captions, assignment and feedback with a student account. Recording and publication are production tasks tracked separately from this syllabus.
